# MVP 里程碑规划

## 第一章：规划概览

### 投入假设

- 业余独立开发，每周 10-15 小时
- 技术栈：Rust (Tauri 2.0 + core crate + CLI) + React 19 + TypeScript + React Flow 12
- 开发者具备 Rust 基础但非日常主力语言

### 交付原则

- 每个里程碑产出可演示的完整用户场景（非半成品模块）
- 优先跑通端到端流程，再逐步加深每个环节
- 每个里程碑结束时，用户可以用一句话描述"这次能做什么了"

### 总时间线概览

```
MS0  工程基座 + 项目管理     ~2 周    第 1-2 周
MS1  主体库 + 账号管理       ~3 周    第 3-5 周
MS2  AI 生图/生视频          ~4 周    第 6-9 周
MS3  节点画布               ~4 周    第 10-13 周
MS4  批量生成 + 多模型       ~3 周    第 14-16 周
MS5  视频后期               ~4 周    第 17-20 周
MS6  配音 + 成片闭环         ~3 周    第 21-23 周
```

总计约 23 周（约 5.5 个月）

## 第三章：各里程碑详情

### MS0: 工程基座 + 项目管理

**目标**：搭建完整的工程骨架，跑通 Tauri + React + SQLite + CLI 全链路，验证技术栈可行性。

**覆盖能力**：基础设施（不直接对应 M1-M8）

**核心任务清单**：

1. 初始化 Cargo workspace（crates/core + crates/cli + src-tauri）
2. 初始化 Tauri 2.0 + React 19 + Vite 6 + pnpm 前端工程
3. 配置 Tailwind CSS 4 + shadcn/ui
4. SQLite 全量 schema 定义 + 迁移框架（rusqlite + 手动迁移脚本）
5. Project 表 CRUD 实现（core crate）
6. Tauri IPC 层：expose project commands
7. CLI 骨架：mango project create / mango project list
8. ts-rs 类型生成管线跑通（Rust struct → TypeScript interface）
9. 基础 App Shell UI（侧边栏 + 顶部导航 + 路由框架）
10. 项目创建/打开/列表页面

**交付物**：

- 可运行的桌面应用（空壳 + 项目管理）
- 可运行的 CLI（mango project create/list）
- 全量数据库 schema（14 核心表 + 3 关联表 + EpisodeCheckpoint）

**演示故事**：打开应用 → 创建一个叫"我的第一部漫剧"的项目 → 在 CLI 中 `mango project list` 看到同一个项目

**前置依赖**：无

**预估工时**：20-30 小时（~2 周）

### MS1: 主体库 + 账号管理

**目标**：能创建和管理创作所需的角色/场景/道具/服装资产，能配置外部 AI 模型的 API 账号。

**覆盖能力**：M1（主体库）+ M8（账号管理）+ M2（素材管理-部分）

**核心任务清单**：

1. Character CRUD（core + Tauri command + React UI）
2. Scene CRUD（同上）
3. Prop CRUD（同上）
4. Costume CRUD（同上，关联 Character）
5. 主体列表页（卡片式展示，带缩略图）
6. 主体详情/编辑页（表单 + 参考图预览）
7. 素材导入管线：拖入文件 → 复制到 assets/ → 生成缩略图 → Asset 入库
8. Provider/Model 预置数据（可灵/即梦的基本信息）
9. ApiAccount CRUD + keyring 加密存储
10. 账号管理 UI（添加/编辑/删除 API Key，显示用量）
11. CLI: mango character list / mango character create / mango account add

**交付物**：

- 角色/场景/道具/服装的完整管理界面
- 参考图拖入导入功能
- API 账号配置界面（密钥安全存储）
- CLI 账号和角色管理命令

**演示故事**：创建角色"小明" → 拖入参考图 → 填写外貌描述"黑发少年，校服" → 切到设置页 → 添加可灵 API Key → 验证连接成功

**前置依赖**：MS0

**预估工时**：30-45 小时（~3 周）

### MS2: AI 生图/生视频

**目标**：跑通第一个端到端的 AI 生成流程——选角色、填 prompt、提交任务、看到生成结果。

**覆盖能力**：M3（Provider 对接-首个）+ M4（任务引擎-基础）

**核心任务清单**：

1. ModelProvider trait 定义（submit/poll/cancel/download）
2. 可灵 Provider 实现（HTTP API 对接、认证、错误处理）
3. 任务引擎基础：单任务提交 + tokio 异步轮询 + 状态机（Pending→Running→Success/Failed）
4. 结果下载 + 自动创建 Asset（file copy + thumbnail + DB 入库）
5. Tauri event 进度推送（任务状态变更实时通知前端）
6. 任务提交表单 UI（选角色/场景 → 填 prompt → 选模型 → 提交）
7. 任务面板 UI（任务列表 + 实时状态 + 进度指示）
8. 结果预览 UI（图片直接展示，视频显示缩略图 + 点击播放）
9. CLI: mango task submit --provider kling --prompt "..." / mango task status <id>
10. 基本错误处理（API 限流、网络超时、余额不足等）

**交付物**：

- 可灵 Provider 完整集成
- 任务提交 + 异步轮询 + 结果下载全链路
- 任务管理面板 UI
- CLI 任务提交和查询

**演示故事**：打开项目 → 进入任务面板 → 选角色"小明" → 输入提示词"小明在教室里看书" → 选择可灵模型 → 点击生成 → 看到状态从"排队中"变为"生成中" → 3 分钟后看到 AI 生成的图片

**前置依赖**：MS1（需要角色数据 + API 账号）

**预估工时**：40-60 小时（~4 周）

### MS3: 节点画布

**目标**：实现核心差异化功能——漫剧业务语义的节点画布，用户能在画布上可视化编排剧情和素材。

**覆盖能力**：M5（节点画布）

**核心任务清单**：

1. React Flow 集成 + 基础画布配置（缩放/平移/minimap/controls）
2. ScriptNode（剧本节点）：显示剧本文本，可展开编辑
3. StoryboardNode（分镜节点）：显示分镜摘要 + 缩略图 + 状态标记
4. CharacterNode（角色节点）：显示角色名 + 参考图缩略图
5. TaskNode（任务节点）：显示生成任务状态 + 结果预览
6. AssetNode（素材节点）：显示图片/视频缩略图 + 文件信息
7. 自定义 Edge 样式（业务关系连线：角色→分镜、分镜→任务、任务→素材）
8. 素材面板 → 画布拖放（HTML5 DnD，dataTransfer 携带 asset_id）
9. 系统文件 → 画布拖放（Tauri onDragDropEvent，自动 import_asset）
10. 拖放到分镜节点上：绑定素材为参考图/采用视频
11. CanvasLayout 持久化（防抖 1s 自动保存到 DB）
12. Undo/Redo（Zustand + zundo，栈深度 50）
13. 画布工具栏（缩放、适应视图、撤销、重做、保存版本）

**交付物**：

- 5 种自定义业务节点
- 画布编排完整交互（拖拽/连线/分组/缩放）
- 系统文件和内部面板双路拖放
- 画布持久化 + Undo/Redo

**演示故事**：打开第一集画布 → 创建剧本节点"第一幕：开学" → 拖出 3 个分镜节点 → 连接角色"小明" → 从素材面板拖入之前生成的图片 → 放到分镜上作为参考图 → Ctrl+Z 撤销 → Ctrl+Y 重做

**前置依赖**：MS2（需要已有的素材和生成任务数据）

**预估工时**：40-60 小时（~4 周）

### MS4: 批量生成 + 多模型

**目标**：支持多模型对比选择和批量生成，实现"抽卡"式创作流程，并引入版本管理保护创作成果。

**覆盖能力**：M3（第二个 Provider）+ M4（任务引擎-完善）+ 版本管理

**核心任务清单**：

1. 即梦 Provider 实现（submit/poll/cancel/download）
2. 任务引擎增强：批量提交（多个分镜 x 多个模型 = N 个任务）
3. 并发控制（bounded channel，可配置最大并发数，默认 3）
4. 失败重试（指数退避，最大 3 次）
5. 批量抽卡对比 UI（同一分镜的多次生成结果并排展示，一键采用）
6. EpisodeCheckpoint 创建/恢复/删除（core crate）
7. 版本历史面板 UI（列表 + change_summary + 恢复确认）
8. 自动保存检查点（重大操作前 + 定时 30 分钟）
9. 检查点清理策略实现
10. CLI: mango checkpoint list / mango checkpoint create / mango checkpoint restore

**交付物**：

- 即梦 Provider 完整集成
- 批量生成 + 并发控制 + 重试
- 抽卡对比界面
- 版本检查点管理（创建/恢复/自动清理）

**演示故事**：选中第三集全部 8 个分镜 → 分别用可灵和即梦各生成一次 → 16 个结果并排对比 → 逐个选择最佳 → 点击"保存版本" → 标记为"分镜定稿" → 继续修改 → 发现改坏了 → 恢复到"分镜定稿"版本

**前置依赖**：MS2（任务引擎基础）；与 MS3 无严格依赖，可交换顺序

**预估工时**：30-45 小时（~3 周）

---

### MS5: 视频后期

**目标**：将 AI 生成的视频片段裁剪、拼接、叠加字幕和漫画气泡，产出可观看的连续视频段落。

**覆盖能力**：M6（视频裁剪 + 字幕/气泡）

**核心任务清单**：

1. FFmpeg sidecar 集成（ffmpeg-sidecar crate + Tauri externalBin 配置）
2. 视频裁剪命令封装（trim：指定起止时间）
3. 视频分割命令封装（split：按时间点切割）
4. 视频拼接命令封装（concat：多片段按顺序合并）
5. 进度解析（解析 FFmpeg stderr 输出，提取处理进度百分比）
6. 基础时间轴 UI（单轨，可视化裁剪标记，拖动调整起止点）
7. 片段排序 UI（拖拽调整拼接顺序）
8. 漫画对话框/旁白气泡叠加层（文本输入 + 样式选择 + 位置拖动）
9. 字幕烧录（SRT 格式 → FFmpeg drawtext/ASS filter）
10. SQLite 文件备份（mango backup create/restore/list）
11. CLI: mango export clip / mango backup create

**交付物**：

- FFmpeg 视频裁剪/分割/拼接全套封装
- 基础时间轴裁剪 UI
- 漫画气泡叠加功能
- 项目文件备份功能

**演示故事**：选中 3 个已生成的视频片段 → 分别裁剪掉头尾多余部分 → 在第二个片段上添加漫画对话气泡"你好啊！" → 按顺序拼接成一个完整片段 → 预览播放

**前置依赖**：MS2（需要已生成的视频素材），建议在 MS4 之后进行

**预估工时**：40-60 小时（~4 周）

---

### MS6: 配音 + 成片闭环

**目标**：补齐"声音"维度，实现从剧本到带配音成片的完整创作闭环。

**覆盖能力**：M7（配音/音效）

**核心任务清单**：

1. AI 配音 Provider 接入（复用 ModelProvider trait，适配 TTS 类型）
2. 候选配音服务调研 + 选型（MiniMax / ChatTTS / FishSpeech 等）
3. 角色声音绑定（Character 表扩展 voice_id 字段，绑定音色）
4. 配音生成流程（从分镜 dialogue 文本 → 提交 TTS 任务 → 下载音频 → Asset 入库）
5. 音效素材库（内置基础音效 + 用户自定义导入）
6. 分镜音效匹配 UI（为分镜选择/绑定背景音效）
7. 音画对齐（配音时长与视频时长匹配，必要时调整语速或填充静音）
8. 最终合成（视频 + 配音 + 音效 + 字幕 → FFmpeg 混合输出）
9. 导出设置 UI（分辨率/码率/格式选择）
10. CLI: mango export final --episode ep01

**交付物**：

- AI 配音集成（至少 1 家 TTS Provider）
- 角色声线绑定 + 批量配音生成
- 音效匹配
- 最终成片导出

**演示故事**：为角色"小明"选择少年音色 → 一键为全集对白生成配音 → 为打斗分镜添加音效 → 点击"导出成片" → 得到一个带对白配音、背景音效和字幕的完整短视频 → MVP 全流程闭环

**前置依赖**：MS5（需要视频编辑能力）

**预估工时**：30-45 小时（~3 周）

## 第五章：风险与调整策略

| 风险                       | 影响                       | 调整策略                                                                                       |
|----------------------------|----------------------------|------------------------------------------------------------------------------------------------|
| Rust 学习曲线拖慢 MS0/MS1  | 前两个里程碑可能超时 50%   | 预留 buffer；MS0 中 schema 可先定义核心表，其余表推迟到实际使用时补充                          |
| 外部 API 变更或下线        | Provider 实现需要重写      | Provider trait 隔离影响范围；优先对接 API 稳定的服务                                           |
| 画布性能（节点过多）       | 100+ 节点时卡顿            | React Flow 官方虚拟化方案；单集分镜控制在 50 以内                                              |
| 配音服务选型不确定         | MS6 可能需要临时调研       | MS2 完成后即开始调研候选 TTS 服务，不等到 MS6                                                  |
| 业余时间不稳定             | 某些周投入不足 10h         | 里程碑以"完成度"而非"日历周"为准；每个 MS 之间不设硬性日期                                     |
| 范围蔓延                   | 开发过程中想加新功能       | 严格对照 M1-M8 范围，新想法记入 V2 backlog                                                     |

### 调整原则

- 里程碑之间可以调序（如先做 MS4 再做 MS3），但 MS0→MS1→MS2 的链路不可打乱
- 如果某个 MS 超时 2 倍以上，需要回头审视是否范围过大，考虑拆分
- 每个 MS 结束时做一次 5 分钟回顾：实际耗时 vs 预估、遇到的意外、下个 MS 的风险点
