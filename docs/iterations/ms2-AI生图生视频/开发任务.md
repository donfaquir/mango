# MS2: AI 生图/生视频

## 迭代目标

跑通第一个端到端的 AI 生成流程——选角色、填 prompt、提交任务、看到生成结果。

**预估工时**：40-60 小时（~4 周）

**前置依赖**：MS1（需要角色数据 + API 账号）

---

## 任务清单

### 任务 1：ModelProvider trait 定义

**任务描述**：定义统一的模型提供商抽象接口。

**开发概设**：
```rust
#[async_trait]
pub trait ModelProvider: Send + Sync {
    async fn submit(&self, params: GenerationParams) -> Result<String>;
    async fn poll(&self, task_id: &str) -> Result<TaskStatus>;
    async fn cancel(&self, task_id: &str) -> Result<()>;
    async fn download(&self, task_id: &str, dest: &Path) -> Result<PathBuf>;
}
```
- 定义 `GenerationParams` 结构体（prompt, negative_prompt, model_id, 参数 JSON）
- 定义 `TaskStatus` 枚举（Pending, Running, Success, Failed, Cancelled）
- 放置在 `crates/core/src/provider/traits.rs`

**验收标准**：
- [ ] trait 定义完整，包含 submit/poll/cancel/download 四个方法
- [ ] GenerationParams 覆盖常用生成参数
- [ ] TaskStatus 包含必要的状态信息（如 progress 百分比、错误消息）

### 任务 2：可灵 Provider 实现

**任务描述**：基于 ModelProvider trait 实现可灵 API 对接。

**开发概设**：
- HTTP API 对接：使用 `reqwest` 调用可灵 REST API
- 认证：Bearer Token（从 keyring 获取）
- 实现 submit（提交生成任务）、poll（轮询结果）、cancel（取消）、download（下载结果文件）
- 错误处理：API 限流(429)、网络超时、认证失败、余额不足

**验收标准**：
- [ ] 可成功提交图片/视频生成任务
- [ ] 轮询正确返回任务状态和进度
- [ ] 下载结果文件到指定路径
- [ ] 各类错误有明确的错误信息

---

### 任务 3：任务引擎基础

**任务描述**：实现单任务提交 + 异步轮询 + 状态机管理。

**开发概设**：
- 任务状态机：Pending → Running → Success/Failed/Cancelled
- tokio spawn 异步任务：提交后启动轮询 loop（间隔 5s）
- 状态变更时通过 tokio-rusqlite 异步更新 GenerationTask 表（不阻塞 runtime）
- 通过 channel 通知状态变更（供 Tauri event 推送）

**验收标准**：
- [ ] 提交任务后 GenerationTask 表记录正确
- [ ] 异步轮询直到任务完成或失败
- [ ] 状态变更可被外部监听
- [ ] 应用退出时正在运行的任务标记为 pending（下次可恢复）

---

### 任务 4：结果下载 + 自动创建 Asset

**任务描述**：任务成功后自动下载结果并创建 Asset 入库。

**开发概设**：
- 任务成功时调用 Provider.download() 下载文件
- 文件保存到项目 `assets/` 目录
- 自动生成缩略图
- 创建 Asset 记录，关联到 GenerationTask.result_asset_id

**验收标准**：
- [ ] 生成完成后结果文件自动下载到本地
- [ ] Asset 表记录完整（包含 content_hash）
- [ ] 缩略图正确生成
- [ ] GenerationTask 的 result_asset_id 正确关联

---

### 任务 5：Tauri event 进度推送

**任务描述**：通过 Tauri event 系统将任务状态变更实时推送到前端。

**开发概设**：
- 定义事件类型：`task-status-changed`，payload 包含 task_id, status, progress
- payload 类型通过 ts-rs `#[derive(TS)]` 导出到前端（event 不走 tauri-specta command 通道）
- 任务引擎状态变更时通过 AppHandle.emit() 推送
- 前端通过 `listen()` 监听事件，收到后 invalidate TanStack Query 的任务列表缓存实现自动刷新

**验收标准**：
- [ ] 前端能实时收到任务状态变更通知
- [ ] 事件 payload 类型在前端有完整 TypeScript 定义
- [ ] 多任务并发时事件不丢失不错乱
- [ ] 收到事件后任务列表自动更新（无需手动刷新）

### 任务 6：任务提交表单 UI

**任务描述**：实现任务提交的前端界面。

**开发概设**：
- 表单流程：选择角色/场景 → 填写 prompt → 选择模型 → 提交
- 角色/场景选择器：下拉列表，显示名称和缩略图
- Prompt 输入：多行文本框，支持引用角色外貌描述
- 模型选择：按 Provider 分组，显示可用模型
- 提交后跳转到任务面板

**验收标准**：
- [ ] 可从已有角色/场景中选择
- [ ] Prompt 可手动输入或引用角色外貌描述自动填充
- [ ] 只显示已配置 API Key 的 Provider 下的模型
- [ ] 提交后表单正确发送数据到后端

### 任务 7：任务面板 UI

**任务描述**：实现任务列表和实时状态展示面板。

**开发概设**：
- 任务列表：按时间倒序，显示任务类型/状态/提交时间

- 状态颜色：排队中(灰)、生成中(蓝+动画)、成功(绿)、失败(红)
- 失败任务显示错误信息，支持重试

**验收标准**：
- [ ] 任务列表完整展示所有任务
- [ ] 状态变更实时更新（无需手动刷新）
- [ ] 进度条正确显示
- [ ] 失败任务可一键重试

### 任务 9：CLI 任务命令

**任务描述**：实现 CLI 下的任务提交和状态查询命令。

**开发概设**：
- `mango task submit --provider kling --prompt "..." --type image`
- `mango task status <task_id>`
- `mango task list [--status running]`
- 提交后轮询输出进度到 stderr

**验收标准**：
- [ ] CLI 提交的任务在 GUI 任务面板可见
- [ ] `task status` 正确显示当前状态
- [ ] 提交时如未配置账号给出明确提示

---

### 任务 10：基本错误处理

**任务描述**：完善 AI 生成流程中的各类错误处理。

**开发概设**：
- API 限流（429）：延迟后重试，通知用户
- 网络超时：重试 + 友好提示
- 余额不足：明确错误信息，引导用户充值
- 认证失败：提示检查 API Key
- 统一错误展示：Toast 通知 + 任务卡片错误信息

**验收标准**：
- [ ] 各类错误有明确、可操作的提示信息
- [ ] 网络临时故障不会导致任务直接失败（有重试）
- [ ] 错误信息对用户友好（非原始 API 错误）
