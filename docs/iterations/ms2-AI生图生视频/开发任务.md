**预估工时**：40-60 小时（~4 周）

## 任务清单

### 任务 1：ModelProvider trait 定义

**任务描述**：定义统一的模型提供商抽象接口。

**开发概设**：
```rust
#[async_trait]
pub trait ModelProvider: Send + Sync {
    async fn submit(&self, params: GenerationParams) -> Result<String>;
    async fn poll(&self, task_id: &str) -> Result<TaskStatus>;
    async fn cancel(&self, task_id: &str) -> Result<()>;
    async fn download(&self, task_id: &str, dest: &Path) -> Result<PathBuf>;
}
```
- 定义 `GenerationParams` 结构体（prompt, negative_prompt, model_id, 参数 JSON）
- 定义 `TaskStatus` 枚举（Pending, Running, Success, Failed, Cancelled）
- 放置在 `crates/core/src/provider/traits.rs`

**验收标准**：
- [ ] trait 定义完整，包含 submit/poll/cancel/download 四个方法
- [ ] GenerationParams 覆盖常用生成参数
- [ ] TaskStatus 包含必要的状态信息（如 progress 百分比、错误消息）

### 任务 2：百炼 Provider 实现（wan2.7-image-pro + happyhorse-1.0-r2v）

**任务描述**：基于 ModelProvider trait 实现阿里云百炼（DashScope）API 对接，**一个 Provider 复用两个模型**：

- `wan2.7-image-pro`（通义万相 2.7 Pro，文生图）—— 任务类型 `image`
- `happyhorse-1.0-r2v`（快乐马，参考图生视频）—— 任务类型 `video`，输入必须绑定一个带参考图的主体

**开发概设**：
- HTTP API 对接：使用 `reqwest` 调用百炼 DashScope REST API
  - base_url：`https://dashscope.aliyuncs.com/api/v1`（取自 `provider.base_url`，可覆盖）
- 认证：`Authorization: Bearer <DASHSCOPE_API_KEY>`（从 keyring 获取），两个模型共用同一鉴权
- **调用模式分歧**：
  - `wan2.7-image-pro`：**同步调用**，请求即响应，单次几十秒内返回结果 URL
  - `happyhorse-1.0-r2v`：**异步任务**，POST submit 拿 `task_id` → GET 轮询任务状态 → 完成后拿结果文件 URL
- **trait 统一外观**：trait 仍只暴露 `submit / poll / cancel / download`。同步模型在 Provider 内部把 `submit` 包装成「立刻调 REST → 把结果缓存到内存 map（key=本地生成的 task_id）→ 返回 task_id」；`poll` 从缓存命中即返回 `Success(result_url)`。**任务引擎和 `generation_task` 状态机不必区分两种模式**，代价仅是同步模型的 Pending→Running→Success 几乎在毫秒内连续触发。
- `wan2.7-image-pro` 请求体（chat-messages 风格，源自官方 SDK 示例）：
  ```json
  {
    "model": "wan2.7-image-pro",
    "input": {
      "messages": [{"role": "user", "content": [{"text": "<prompt>"}]}]
    },
    "parameters": { "n": 1, "size": "2K", "enable_sequential": false }
  }
  ```
  关键参数：`n`（生成几张）、`size`（如 `"2K"`）、`enable_sequential`（组图前后一致）
- `happyhorse-1.0-r2v` 请求体（已确认）：
  - endpoint：`POST /api/v1/services/aigc/video-generation/video-synthesis`
  - 异步标记 header：`X-DashScope-Async: enable`
  - 请求体：
    ```json
    {
      "model": "happyhorse-1.0-r2v",
      "input": {
        "prompt": "...（可在 prompt 内用「图1/图2/图3」引用多张参考图）",
        "media": [
          { "type": "reference_image", "url": "https://..." }
        ]
      },
      "parameters": { "resolution": "720P", "ratio": "16:9", "duration": 5 }
    }
    ```
  - 参数：`resolution`（720P/1080P）、`ratio`（16:9/9:16/1:1）、`duration`（秒）；支持多张参考图

#### 参考图上传：阿里 OSS（已决议 2026-05-25）

主体库的参考图存本地 `<project_root>/assets/<uuid>.png`，happyhorse 只接公网 HTTPS URL。**方案：上传到用户配置的阿里 OSS bucket** → 拿临时签名 URL（默认 1h） → 喂给 happyhorse → 任务终态（成功/失败/取消）后清理 bucket 对应对象。

实施要点：
- 上传层独立模块 `crates/core/src/provider/asset_uploader/`，与 bailian provider 解耦，后续其他只接 URL 的 provider 可复用
- OSS 配置（endpoint / bucket / AK/SK 或 STS）扩 `api_account.params_json` —— 该字段当前仅存在于 `generation_task` 表，`api_account` 需新增 migration 加 TEXT 列；账号管理 UI 加 OSS 表单
- Rust OSS SDK 选型在实施初期确定（阿里官方无 Rust SDK；候选：oss-rust-sdk、aliyun-oss-rust-sdk、自写 reqwest + V4 签名），按 `docs/技术选型.md` 流程走 web 验证后再定
- 上传/清理失败的错误要可识别区分，避免被误归为「happyhorse 接口错」
- 结果文件 URL 通常有有效期（万相系列约 24h），download 紧跟 poll 成功，不可拖延
- 错误处理：API 限流（429）退避重试、网络超时、认证失败、余额不足、参考图 URL 不可达

**验收标准**：
- [ ] `wan2.7-image-pro` 可成功提交并拿到图片
- [ ] `happyhorse-1.0-r2v` 可成功提交（带参考图）并拿到视频
- [ ] 轮询正确返回任务状态和进度
- [ ] 下载结果文件到指定路径
- [ ] 各类错误有明确的错误信息
- [ ] 同一 Provider 实例可按 `model_id` 路由到两个模型

### 任务 3：任务引擎基础

**任务描述**：实现单任务提交 + 异步轮询 + 状态机管理。

**开发概设**：
- 任务状态机：Pending → Running → Success/Failed/Cancelled
- tokio spawn 异步任务：提交后启动轮询 loop（间隔 5s）
- 状态变更时通过 tokio-rusqlite 异步更新 GenerationTask 表（不阻塞 runtime）
- 通过 channel 通知状态变更（供 Tauri event 推送）

**验收标准**：
- [ ] 提交任务后 GenerationTask 表记录正确
- [ ] 异步轮询直到任务完成或失败
- [ ] 状态变更可被外部监听
- [ ] 应用退出时正在运行的任务标记为 pending（下次可恢复）

### 任务 5：Tauri event 进度推送

**任务描述**：通过 Tauri event 系统将任务状态变更实时推送到前端。

**开发概设**：
- 定义事件类型：`task-status-changed`，payload 包含 task_id, status, progress
- payload 类型通过 ts-rs `#[derive(TS)]` 导出到前端（event 不走 tauri-specta command 通道）
- 任务引擎状态变更时通过 AppHandle.emit() 推送
- 前端通过 `listen()` 监听事件，收到后 invalidate TanStack Query 的任务列表缓存实现自动刷新

**验收标准**：
- [ ] 前端能实时收到任务状态变更通知
- [ ] 事件 payload 类型在前端有完整 TypeScript 定义
- [ ] 多任务并发时事件不丢失不错乱
- [ ] 收到事件后任务列表自动更新（无需手动刷新）

### 任务 10：基本错误处理

**任务描述**：完善 AI 生成流程中的各类错误处理。

**开发概设**：
- API 限流（429）：延迟后重试，通知用户

- 统一错误展示：Toast 通知 + 任务卡片错误信息

**验收标准**：
- [ ] 各类错误有明确、可操作的提示信息

- [ ] 错误信息对用户友好（非原始 API 错误）
