# MS0: 工程基座 + 项目管理

## 迭代目标

搭建完整的工程骨架，跑通 Tauri + React + SQLite + CLI 全链路，验证技术栈可行性。

**预估工时**：20-30 小时（~2 周）

**前置依赖**：无

---

## 任务清单

### 任务 1：初始化 Cargo workspace

**任务描述**：创建 Rust workspace monorepo 结构，包含 `crates/core`、`crates/cli`、`src-tauri` 三个 crate。

**开发概设**：
- 根目录 `Cargo.toml` 配置 workspace members
- `crates/core`：核心业务库，`lib` 类型 crate
- `crates/cli`：CLI 二进制，依赖 core
- `src-tauri`：Tauri 桌面应用，依赖 core
- 配置统一的 Rust edition（2021）和公共依赖版本

**验收标准**：
- [ ] `cargo build` 在 workspace 根目录成功编译所有 crate
- [ ] 三个 crate 之间的依赖关系正确
- [ ] `cargo test` 能运行（即使暂无测试用例）

---

### 任务 2：初始化前端工程

**任务描述**：初始化 Tauri 2.0 + React 19 + Vite 8 + pnpm 前端工程，配置 Tailwind CSS 4 + shadcn/ui。

**开发概设**：
- 使用 `create-tauri-app` 或手动初始化 Tauri 2.0 项目
- React 19 + TypeScript 5.8+ 严格模式
- Vite 8 作为前端构建工具（使用 Rolldown 打包器）
- pnpm 11 作为包管理器
- Tailwind CSS 4 配置（CSS-first 模式，使用 `@import "tailwindcss"` 而非旧的 config 文件）
- shadcn/ui 组件库初始化
- 安装 TanStack Query 5.x 用于 IPC 数据层
- 配置 Vitest 用于前端单元测试

**验收标准**：
- [ ] `pnpm dev` 启动前端开发服务器正常
- [ ] `pnpm tauri dev` 启动桌面应用窗口正常
- [ ] Tailwind CSS 4 样式生效（CSS-first 配置模式）
- [ ] shadcn/ui 至少一个组件可正常渲染
- [ ] Vitest 可运行示例测试用例
- [ ] TanStack Query Provider 正确配置

---

### 任务 3：SQLite 全量 schema 定义 + 迁移框架

**任务描述**：在 core crate 中定义完整的数据库 schema，建立手动迁移脚本机制，并配置异步 DB 访问层。

**开发概设**：
- 使用 `rusqlite` 0.39+ 作为 SQLite 驱动
- 使用 `tokio-rusqlite` 提供异步访问包装（避免在 tokio runtime 中阻塞线程）
- 手动迁移脚本方案：`migrations/` 目录下按版本号排列 SQL 文件
- 定义 14 核心表 + 3 关联表 + EpisodeCheckpoint 表
- 迁移执行器：记录已执行的迁移版本，支持增量升级
- 表结构参照技术选型文档中的数据模型设计
- DB 层对外同时暴露同步和异步 API：CLI 使用同步，Tauri 使用异步

**验收标准**：
- [ ] 首次启动时自动创建所有表
- [ ] 迁移脚本幂等执行（重复运行不报错）
- [ ] 所有外键关系正确建立
- [ ] 有基本的迁移版本追踪机制
- [ ] tokio-rusqlite 异步调用在 Tauri 环境下正常工作

---

### 任务 4：Project 表 CRUD 实现

**任务描述**：在 core crate 中实现 Project 实体的创建、读取、更新、删除操作。

**开发概设**：
- `db/queries/project.rs` 实现 CRUD 函数
- Project struct 定义：id (UUID), name, description, style_prompt, global_seed, created_at, updated_at
- 提供同步 API 供 CLI 和 Tauri command 调用
- 使用 `thiserror` 定义错误类型

**验收标准**：
- [ ] 单元测试覆盖 create / get_by_id / list / update / delete
- [ ] ID 使用 UUID v4 自动生成
- [ ] created_at 和 updated_at 自动填充时间戳
- [ ] 删除不存在的项目返回合适的错误

---

### 任务 5：Tauri IPC 层

**任务描述**：通过 `#[tauri::command]` 将 Project CRUD 暴露为 IPC 接口，使用 tauri-specta 生成类型安全绑定。

**开发概设**：
- `src-tauri/src/commands/project.rs` 定义 Tauri commands
- 薄封装 core 函数，仅处理序列化和状态注入
- 统一返回 `Result<T, String>` 格式
- 通过 tauri-specta 注册 commands 并生成 TypeScript 绑定
- 前端通过生成的绑定函数直接调用（无需手写 invoke）

**验收标准**：
- [ ] 前端可通过生成的类型安全函数调用后端（如 `commands.createProject({...})`）
- [ ] 前端可获取项目列表和单个项目详情
- [ ] 错误信息能正确传递到前端
- [ ] IPC 调用无序列化/反序列化错误
- [ ] 新增 command 后重新生成绑定即可使用

### 任务 6：CLI 骨架

**任务描述**：实现 CLI 基础框架，支持 `mango project create` 和 `mango project list` 命令。

**开发概设**：
- 使用 `clap` 4.x derive 模式定义命令结构
- 子命令结构：`mango <subcommand> <action> [options]`
- 直接调用 core crate 函数
- 输出格式：表格形式（project list）或确认信息（project create）

**验收标准**：
- [ ] `mango project create --name "测试项目"` 成功创建并输出项目信息
- [ ] `mango project list` 以表格形式展示所有项目
- [ ] `mango --help` 显示帮助信息
- [ ] CLI 和 GUI 操作同一个数据库文件

---

### 任务 7：tauri-specta + ts-rs 类型生成管线

**任务描述**：配置 tauri-specta 从 Tauri commands 自动生成类型安全的 TypeScript 绑定，ts-rs 用于补充的纯数据结构导出。

**开发概设**：
- **tauri-specta（主方案）**：
  - 集成 `tauri-specta` v2，在 Tauri 应用启动时自动生成 command 绑定
  - 生成的绑定包含完整的函数签名（参数类型 + 返回值类型），前端无需手写 `invoke()`
  - 输出到 `src/lib/bindings/commands.ts`
- **ts-rs（补充）**：
  - 对非 command 的数据结构（如 Tauri event payload）标注 `#[derive(TS)]`
  - 输出到 `src/lib/bindings/types/`
- 前端直接 import 使用，配合 TanStack Query 封装数据获取层

**验收标准**：
- [ ] tauri-specta 生成的绑定文件可直接 import 调用
- [ ] 调用生成的函数具有完整的类型提示（参数 + 返回值）
- [ ] ts-rs 导出的 event payload 类型正确
- [ ] Rust 端变更后重新生成无需手动干预
- [ ] 前端 TypeScript 编译无类型错误

### 任务 8：基础 App Shell UI

**任务描述**：实现应用的基础布局框架，包含侧边栏、顶部导航和路由。

**开发概设**：
- App Shell 布局：左侧边栏 + 顶部导航 + 主内容区
- 使用 React Router 配置基础路由
- 侧边栏：项目列表入口、设置入口
- 顶部导航：面包屑 + 全局操作按钮
- 状态分层：Zustand 管理 UI 状态（侧边栏折叠、当前路由等），TanStack Query 管理数据获取
- 建立 IPC 数据获取的 Query 封装模式（如 `useProjectList()` hook）

**验收标准**：
- [ ] 应用启动后显示完整的 Shell 布局
- [ ] 侧边栏可折叠/展开
- [ ] 路由切换正常，无白屏
- [ ] 响应式布局，窗口缩放后不错位
- [ ] 数据加载状态正确显示（loading/error/success）
