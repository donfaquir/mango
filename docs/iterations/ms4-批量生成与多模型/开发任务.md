# MS4: 批量生成 + 多模型

## 迭代目标

支持多模型对比选择和批量生成，实现"抽卡"式创作流程，并引入版本管理保护创作成果。

**预估工时**：30-45 小时（~3 周）

**前置依赖**：MS2（任务引擎基础）；与 MS3 无严格依赖，可交换顺序

---

## 任务清单

### 任务 1：即梦 Provider 实现

**任务描述**：基于 ModelProvider trait 实现即梦 API 对接。

**开发概设**：
- 参考百炼 Provider 实现结构（MS2 已落地的 trait 适配模式）
- HTTP API 对接：即梦 REST API
- 认证方式适配
- 实现 submit/poll/cancel/download 完整流程

**验收标准**：
- [ ] 可成功提交图片/视频生成任务到即梦
- [ ] 轮询和下载功能正常
- [ ] 错误处理覆盖常见场景
- [ ] 与百炼 Provider 可互换使用

---

### 任务 2：批量提交机制

**任务描述**：实现多分镜 x 多模型的批量任务提交。

**开发概设**：
- 批量提交入口：选中多个分镜 → 选择多个模型 → 生成 N*M 个任务
- 任务分组：同一批次标记 batch_id 方便管理
- 提交前确认：显示将生成的任务数和预估消耗

**验收标准**：
- [ ] 可选中多个分镜进行批量生成
- [ ] 可同时选择多个模型
- [ ] 任务正确创建并按批次分组
- [ ] 提交前有确认提示

---

### 任务 3：并发控制

**任务描述**：实现任务并发数限制，避免 API 调用过载。

**开发概设**：
- bounded channel 实现任务队列
- 可配置最大并发数（默认 3）
- 超出并发数的任务排队等待
- 设置页面可调整并发数

**验收标准**：
- [ ] 同时运行的任务不超过配置的最大并发数
- [ ] 队列中的任务按提交顺序执行
- [ ] 修改并发数配置立即生效

---

### 任务 4：失败重试

**任务描述**：实现任务失败后的自动重试机制。

**开发概设**：
- 指数退避策略：1s → 2s → 4s
- 最大重试次数：3 次
- 仅对可重试错误重试（网络超时、限流），认证失败等不重试
- GenerationTask 表记录 retry_count

**验收标准**：
- [ ] 网络超时自动重试
- [ ] 重试间隔递增
- [ ] 超过最大次数后标记失败
- [ ] 不可重试的错误立即失败

---

### 任务 5：批量抽卡对比 UI

**任务描述**：同一分镜的多次生成结果并排展示，支持一键采用。

**开发概设**：
- 对比视图：grid 布局展示同一分镜的所有生成结果
- 每个结果卡片：缩略图 + 模型名 + 生成时间 + 采用按钮
- 采用操作：将选中结果标记为该分镜的最终素材
- 支持放大对比

**验收标准**：
- [ ] 同一分镜的所有结果并排展示
- [ ] 可区分不同模型的结果
- [ ] 一键采用后分镜状态更新为 done
- [ ] 可放大单张查看细节

---

### 任务 6：EpisodeCheckpoint 创建/恢复/删除

**任务描述**：在 core crate 中实现集级别检查点的完整功能。

**开发概设**：
- 创建检查点：快照当前集的 script_text + shots_json + canvas 布局
- 恢复检查点：全量覆盖当前数据（恢复前自动创建当前状态的检查点）
- 删除检查点：仅删除检查点记录
- 自动生成 change_summary：对比字数差异、分镜数量变化
- version_number 自增

**验收标准**：
- [ ] 创建检查点完整保存当前集状态
- [ ] 恢复后数据与快照时一致
- [ ] 恢复前自动保存当前状态
- [ ] change_summary 自动生成且有意义

---

### 任务 7：版本历史面板 UI

**任务描述**：实现检查点的可视化管理界面。

**开发概设**：
- 侧边面板：按时间倒序展示检查点列表
- 每个条目：版本号 + 标签 + 时间 + change_summary
- 操作：恢复（二次确认）、删除、重命名标签
- 区分手动/自动创建的检查点（图标标记）

**验收标准**：
- [ ] 检查点列表完整展示
- [ ] 恢复时有二次确认弹窗
- [ ] 可为检查点添加/修改标签
- [ ] 手动和自动检查点视觉可区分

---

### 任务 8：自动保存检查点

**任务描述**：实现自动触发检查点创建的机制。

**开发概设**：
- 触发时机：
  - 重大操作前（批量生成前、恢复检查点前）
  - 定时：每 30 分钟（有变更时）
- trigger_type 标记为 "auto"
- 自动检查点不计入手动创建的版本号序列

**验收标准**：
- [ ] 30 分钟内有变更时自动创建检查点
- [ ] 无变更时不创建（避免垃圾数据）
- [ ] 重大操作前正确触发

---

### 任务 9：检查点清理策略

**任务描述**：实现自动检查点的清理规则，避免数据膨胀。

**开发概设**：
- 清理规则：
  - 24h 内保留全部
  - 1-7 天每天保留最后一个
  - 7 天以上每周保留最后一个
  - 手动保存（trigger_type=manual）永不自动清理
- 清理时机：应用启动时 + 每次创建新检查点时

**验收标准**：
- [ ] 清理规则正确执行
- [ ] 手动检查点不被清理
- [ ] 清理后不影响版本历史的连续性

---

### 任务 10：CLI 检查点命令

**任务描述**：实现 CLI 下的检查点管理命令。

**开发概设**：
- `mango checkpoint list --episode <id>`
- `mango checkpoint create --episode <id> --label "分镜定稿"`
- `mango checkpoint restore <checkpoint_id>`

**验收标准**：
- [ ] CLI 创建的检查点在 GUI 版本面板可见
- [ ] restore 前有确认提示
- [ ] list 显示完整的版本历史信息
