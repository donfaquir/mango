# MS7: 视频剪辑增强

## 迭代目标

补齐漫剧成片所需的视觉编辑能力：多轨时间轴、镜头动态化（Ken Burns / 关键帧）、转场、文字系统（字幕/气泡/花字/拟声词）、贴片装饰、视觉特效。使用户在 Mango 内完成从 AI 生图到可发布漫剧视频的全部剪辑工作，无需导出到第三方工具。

**预估工时**：120–160 小时（~8–12 周，拆 8 个任务）

> 修正：原估算 80-110 小时偏乐观。任务 3（多轨时间轴）和任务 6（文字系统）各自复杂度较高，合计占 60+ 小时。

**前置依赖**：MS5（FFmpeg 基础命令 + 单轨时间轴）、MS6（配音/音效/字幕烧录 + 成片合成）

## 任务清单

### 任务 1：FFmpeg filter graph builder

**任务描述**：扩展现有 filter graph builder，新增视频 filter 方法，并创建 `render.rs` 渲染编排模块，为所有视觉效果提供后端基础。

> **修正说明**：`filter_graph.rs` 已存在（184 行），含 `FilterGraph` 结构体 + 6 个音频 filter 方法（volume/adelay/apad/atrim/amix/aconcat），被 `audio.rs` 依赖。此任务是「扩展」而非「新建」。原计划的 `FilterChain` 类型已删除——现有扁平 `Vec<FilterNode>` 模型足够表达线性链和复杂 DAG。

**开发概设**：

**扩展 `crates/core/src/ffmpeg/filter_graph.rs`**（现有 184 行）：
- 保持现有架构不变：`FilterGraph` 使用 flat `Vec<FilterNode>` 模型，不引入 `FilterChain` 类型
- 现有 6 个音频方法保持 API 不变（`volume`, `adelay`, `apad`, `atrim`, `amix`, `aconcat`），`audio.rs` 已依赖这些 API
- 新增视频 filter 方法（类型安全构造器）：
  - `zoompan(input, zoom_expr, x_expr, y_expr, duration_frames, fps, output)` — Ken Burns 动画
  - `xfade(input_a, input_b, transition, duration_secs, offset_secs, output)` — 转场效果
  - `drawtext(input, text, fontfile, fontsize, fontcolor, x, y, enable_expr, output)` — 文字叠加
  - `overlay(main_input, overlay_input, x, y, enable_expr, output)` — 贴片/水印/气泡叠加
  - `scale(input, width, height, output)` — 缩放
  - `pad(input, width, height, x, y, color, output)` — 填充（宽高比变换）
  - `colorbalance(input, rs, gs, bs, rm, gm, bm, rh, gh, bh, output)` — 调色
  - `eq(input, brightness, contrast, saturation, output)` — 亮度/对比度/饱和度
  - `fps(input, fps, output)` — 帧率统一
  - `format(input, pix_fmt, output)` — 像素格式统一
  - `concat(inputs, n_segments, has_video, has_audio, output_v, output_a)` — 视频+音频 concat
- 新增 `normalize` 便捷方法：
  - `normalize(input, width, height, fps, pix_fmt, output)` — 组合 `scale` + `fps` + `format` 成一条 filter chain
  - 用途：xfade 和 concat 要求所有输入具有相同分辨率、帧率、像素格式，`normalize` 保证这一前置条件
  - 注：现有 `check_concat_compatibility()`（commands.rs:273）仅检查 `-c copy` 模式的兼容性（分辨率/fps/codec/audio），不检查 pixel format；Render 模式下由 `normalize` 保证

**新建 `crates/core/src/ffmpeg/render.rs`**，封装完整渲染编排：
- `RenderConfig`：编码参数结构体（codec, preset, crf, audio_bitrate, container_format）
- `render_timeline(config, ffmpeg_config, timeline_data, output_path, on_progress)` — 主入口
- 渲染流程：
  1. 为每个输入 clip 生成 normalize filter chain → 统一分辨率/帧率/像素格式
  2. 为需要 Ken Burns 的 clip 生成 zoompan filter
  3. 在相邻 clip 之间插入 xfade filter（如有转场）
  4. 叠加文字/贴片 overlay
  5. 混合音频（复用现有 `audio.rs` 的 filter graph 模式）
  6. 最终 concat + 编码输出
- 进度计算复用 `progress.rs` 的 `FfmpegProgressParser`
- 在 `mod.rs` 中注册 `pub mod render;` 并 re-export 主要类型

**验收标准**：
- [ ] 现有 6 个音频 filter 方法 API 不变，`audio.rs` 的调用无需修改
- [ ] `FilterGraph::build()` 对 3 个视频输入 + normalize + xfade 生成正确的 `-filter_complex` 字符串
- [ ] `normalize` 方法生成 `[in]scale=W:H,fps=F,format=FMT[out]` 格式的 filter chain
- [ ] 生成的命令可被 FFmpeg 正确执行（集成测试用真实 FFmpeg）
- [ ] 单元测试覆盖各 video filter 构造器的参数序列化（至少 zoompan, xfade, drawtext, overlay, normalize）
- [ ] 复杂 graph（5+ 输入、视频+音频混合 filter）生成的命令无语法错误
- [ ] `render_timeline()` 可执行端到端渲染（3 个 clip + 1 个转场 + 1 个文字叠加 → 输出 mp4）

### 任务 2：重编码导出管线

**任务描述**：新增基于 filter graph 的重编码导出管线，使转场、特效、文字叠加成为可能。保留现有 MS5/MS6 的 Copy 模式导出函数不变。

> **修正说明**：原计划要修改 `export_resolved_clips()`，但该函数是 MS5/MS6 的简单导出路径（读 `video_clip` 表 + `shot_audio` 表，`-c copy` concat），不应改动。新建 `export_timeline()` 读 `timeline_*` 表。此外新增输入归一化步骤——xfade 要求所有输入同分辨率/帧率/像素格式，现有 `check_concat_compatibility()` 仅检查 `-c copy` 兼容性，不检查 pixel format。

**开发概设**：

**保持现有导出函数不变**（向后兼容）：
- `export.rs` 中 `export_resolved_clips()` 和 `export_final()` 继续作为 MS5/MS6 的简单导出路径
- `src-tauri/src/commands/video.rs` 中 `export_video_clips` 和 `export_final` Tauri 命令保持不变
- 这些函数读 `video_clip` 表 + `shot_audio` 表，使用 `-c copy` concat 模式

**新增 `ExportMode` 枚举**（在 `export.rs` 中）：
- `Copy`：当前行为，快速无转码拼接
- `Render`：通过 filter graph 重编码输出

**新增输入归一化步骤**（normalize pipeline）：
- 在进入 filter graph 前，对每个输入 clip 执行归一化：
  - 目标分辨率：取第一个 clip 的分辨率，或由用户指定输出分辨率
  - 目标帧率：统一为 30fps（默认）或用户指定
  - 目标像素格式：统一为 `yuv420p`（H.264 要求）
- 归一化通过任务 1 的 `FilterGraph::normalize()` 方法实现

**扩展 `probe.rs`**（微调）：
- 在 `VideoMetadata` 结构体中新增 `pixel_format: Option<String>` 字段
- 从 ffprobe 的 `pix_fmt` 字段读取（如 `yuv420p`, `yuv444p`）
- 用于 normalize 步骤决定是否需要像素格式转换

**新增 `export_timeline()` 函数**（在 `export.rs` 中）：
- 签名：`export_timeline(conn, episode_id, workspace_root, render_config, ffmpeg_config, on_progress) -> Result<PathBuf>`
- 数据源：读 `timeline_track` + `timeline_item` + `timeline_keyframe` 表（任务 3 新建）
- 管线流程：
  1. 从 DB 查询 timeline 数据 → 构建 `TimelineData` 结构
  2. 智能降级判断：如果所有 item 无 filter/无转场/同参数 → 自动使用 Copy 模式（复用现有 `concat_videos()`）
  3. Render 模式：调用 `render.rs` 的 `render_timeline()` 执行完整 filter graph 渲染
- 不修改、不替代现有的 `export_resolved_clips` / `export_final`

**Render 模式编码参数**（`RenderConfig` 结构体，定义在 `render.rs`）：
- 视频：libx264（默认）/ libx265（可选），preset 可配置（ultrafast → slow），CRF 可配置（默认 18）
- 音频：aac 128k
- 容器：mp4（默认）、webm（可选）

**Tauri IPC 扩展**：

- 保留现有 `export_video_clips` 和 `export_final` 命令不变

**CLI 扩展**：

**验收标准**：
- [ ] 现有 `export_video_clips` / `export_final` Tauri 命令行为不变，MS5/MS6 导出流程正常
- [ ] 无特效时间轴自动使用 Copy 模式，速度与 MS5 一致

多轨时间轴将二者合一：clip 列表成为视频轨上的 item，裁剪成为 item 的 in/out point 操作。

**开发概设**：

**数据模型**（DB migration 015_timeline）：

```sql
-- timeline_track 表
CREATE TABLE timeline_track (
    id          TEXT PRIMARY KEY NOT NULL,
    episode_id  TEXT NOT NULL REFERENCES episode(id) ON DELETE CASCADE,
    track_type  TEXT NOT NULL CHECK(track_type IN ('video','audio','text','overlay')),
    label       TEXT NOT NULL,
    order_index INTEGER NOT NULL,
    muted       INTEGER NOT NULL DEFAULT 0,
    locked      INTEGER NOT NULL DEFAULT 0,
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_timeline_track_episode ON timeline_track(episode_id, order_index);

-- timeline_item 表
CREATE TABLE timeline_item (
    id            TEXT PRIMARY KEY NOT NULL,
    track_id      TEXT NOT NULL REFERENCES timeline_track(id) ON DELETE CASCADE,
    asset_id      TEXT REFERENCES asset(id),
    item_type     TEXT NOT NULL CHECK(item_type IN ('clip','text','sticker','transition','effect')),
    position_ms   INTEGER NOT NULL,
    duration_ms   INTEGER NOT NULL,
    in_point_ms   INTEGER NOT NULL DEFAULT 0,
    out_point_ms  INTEGER NOT NULL,
    params_json   TEXT NOT NULL DEFAULT '{}',
    order_index   INTEGER NOT NULL DEFAULT 0,
    created_at    TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_timeline_item_track ON timeline_item(track_id, position_ms);

-- timeline_keyframe 表（本任务建表，任务 4 使用）
CREATE TABLE timeline_keyframe (
    id         TEXT PRIMARY KEY NOT NULL,
    item_id    TEXT NOT NULL REFERENCES timeline_item(id) ON DELETE CASCADE,
    property   TEXT NOT NULL CHECK(property IN ('position_x','position_y','scale','rotation','opacity')),
    time_ms    INTEGER NOT NULL,
    value      REAL NOT NULL,
    easing     TEXT NOT NULL DEFAULT 'linear' CHECK(easing IN ('linear','ease_in','ease_out','ease_in_out')),
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_timeline_keyframe_item ON timeline_keyframe(item_id, property, time_ms);
```

### 任务 4：关键帧动画系统 + Ken Burns 预设

**任务描述**：实现关键帧动画系统，支持对 item 的位置/缩放/旋转/透明度做时间插值动画。并提供 Ken Burns 动态预设，一键应用镜头运动。

**开发概设**：

**关键帧系统**：
- 后端：`timeline_keyframe` 表（见任务 3），CRUD 查询
- 前端：`useKeyframes.ts` hook，`KeyframeEditor.tsx` 组件
  - 在 item 详情面板中显示关键帧时间线
  - 可添加/删除/拖动关键帧节点
  - 支持 4 种缓动曲线：`linear`, `ease_in`, `ease_out`, `ease_in_out`
  - 可动画化的属性：`position_x`, `position_y`, `scale`, `rotation`, `opacity`
- FFmpeg 映射：关键帧数据 → `zoompan` filter 参数（position/zoom 随时间变化）
  - `zoompan=z='if(between(in_time,0,3),1+0.001*in_time*25,1.075)':x='...':y='...'`
  - 复杂情况：多段 keyframe → 拼接多个 zoompan 表达式

**Ken Burns 预设**：
- 内置 8 个常用预设（存储为预定义 keyframe 序列）：

| 预设名 | 效果 | 参数 |
|---|---|---|
| 缓慢推进 | 从全景缓慢放大到中心 | scale: 1.0 → 1.15, 4s |
| 缓慢拉远 | 从中心放大状态缓慢缩小 | scale: 1.15 → 1.0, 4s |
| 左移 | 画面从右向左平移 | x: 0% → -10%, 4s |
| 右移 | 画面从左向右平移 | x: -10% → 0%, 4s |
| 上移 | 画面从下向上平移 | y: 0% → -10%, 4s |
| 下移 | 画面从上向下平移 | y: -10% → 0%, 4s |
| 推进+右移 | 组合：放大+平移 | scale+x 组合 |
| 戏剧推进 | 快速推进到特定区域 | scale: 1.0 → 1.4, ease_in, 2s |

- 用户选择预设后自动创建对应的 keyframe 序列，之后可手动微调
- 批量应用：选中多个 clip → 一键套用相同预设

**其他镜头特效**（基于 filter）：
- 镜头抖动：`crop` filter + 随机偏移表达式
- 闪白/闪黑：在两个 clip 之间插入纯色帧 + fade
- 定格：复制最后一帧 → 延长为指定时长的静态片段

**验收标准**：
- [ ] 可为 clip 添加/编辑/删除关键帧
- [ ] 关键帧时间线可视化正确
- [ ] 4 种缓动曲线在导出视频中效果正确
- [ ] 8 个 Ken Burns 预设一键应用，导出视频动效符合预期
- [ ] 预设应用后可手动修改关键帧
- [ ] 批量应用预设到多个 clip
- [ ] 镜头抖动效果在导出中正确渲染

### 任务 5：转场库

**任务描述**：实现视频片段之间的转场效果，提供漫剧常用的转场类型。

**开发概设**：

- 转场时长可拖拽调整（默认 500ms，范围 100ms–2000ms）

| 圆形收缩 | `circleclose` | 漫画风 |
| 像素化 | `pixelize` | 风格化 |

- 转场预览：在时间轴上 hover 转场图标时显示缩略图预览（取两个 clip 的边界帧合成）

### 任务 6：文字系统

**任务描述**：实现完整的文字系统，包括样式化字幕、漫画气泡、花字标题、拟声词，支持模板和动画。

**开发概设**：

**数据模型**：文字作为 `timeline_item`（`item_type = 'text'`）放在文字轨上，`params_json` 存储：
```json
{
  "text_type": "subtitle|bubble|fancy|onomatopoeia",
  "content": "震惊！",
  "style": {
    "font_family": "Noto Sans SC",
    "font_size": 48,
    "font_weight": "bold",
    "color": "#FFFFFF",
    "outline_color": "#000000",
    "outline_width": 2,
    "shadow": true,
    "background": { "type": "none|solid|gradient|image", "value": "..." },
    "position": { "x": 0.5, "y": 0.9 },
    "alignment": "center",
    "vertical": false
  },
  "bubble": {
    "shape": "oval|rect|cloud|shout|whisper",
    "tail_direction": "bottom_left",
    "fill_color": "#FFFFFF",
    "border_color": "#000000"
  },
  "animation": {
    "enter": "none|fade_in|pop_in|typewriter|slide_up",
    "exit": "none|fade_out|pop_out|slide_down",
    "enter_duration_ms": 300,
    "exit_duration_ms": 300
  },
  "template_id": "fancy_shock_01"
}
```

**四种文字类型**：

1. **字幕**（subtitle）：
   - 位于画面底部，支持角色分色（按角色 ID 自动着色）
   - 字幕动画：淡入/逐字出现/弹入
   - 可从 MS6 的 ASS/SRT 数据自动导入，但允许在时间轴上手动编辑

2. **漫画气泡**（bubble）：
   - 5 种气泡形状：圆形对话泡、圆角矩形、云形思考泡、尖角喊叫泡、虚线耳语泡
   - 气泡尾巴方向可调（8 个方位）
   - 气泡内文字自动排版（自动换行、居中）
   - FFmpeg 实现：预渲染气泡为 PNG → `overlay` filter 叠加
   - 气泡 PNG 渲染：后端使用 `resvg`（已有 SVG 能力）或前端 Canvas 预渲染

3. **花字**（fancy text）：
   - 带装饰性背景的大字标题（如「震惊！」「三年后...」「VS」）
   - **模板库**：内置 15-20 个花字模板，按风格分类（热血、搞笑、恐怖、浪漫、悬疑）
   - 每个模板定义：字体、字号、颜色方案、描边、阴影、背景装饰、入场/出场动画
   - 用户选择模板 → 输入文字 → 自动生成；可微调参数

4. **拟声词**（onomatopoeia）：
   - 漫画特有的视觉音效文字：「砰！」「嗖！」「咔嚓！」
   - 特点：大字号、倾斜、手绘/毛笔风格字体、通常带描边和阴影
   - 位置自由放置（不限于底部），可旋转
   - 内置 10+ 常用拟声词模板

**文字编辑 UI**：
- `TextEditorPanel.tsx`：选中文字 item 后在右侧显示编辑面板
  - 文字类型选择
  - 内容输入（富文本）
  - 样式控制（字体/字号/颜色/描边/阴影）
  - 气泡设置（仅 bubble 类型）
  - 动画设置
  - 模板选择器
- `TextTemplateGallery.tsx`：花字/拟声词模板网格，预览 + 一键应用

**FFmpeg 渲染**：
- 字幕：`drawtext` filter（简单文字）或 ASS filter（复杂样式）
- 气泡/花字/拟声词：预渲染为透明 PNG → `overlay` filter 叠加
  - 预渲染时机：导出前，在 core 层完成
  - 动画：通过 `overlay` 的 `enable` 参数 + `fade` filter 实现 enter/exit

**验收标准**：
- [ ] 可在文字轨添加 4 种文字类型
- [ ] 字幕支持角色分色和 3 种入场动画
- [ ] 5 种气泡形状正确渲染，尾巴方向可调
- [ ] 花字模板库可浏览和应用
- [ ] 拟声词可自由定位和旋转
- [ ] 文字编辑面板实时预览样式
- [ ] 导出视频中所有文字类型正确叠加
- [ ] 可从 MS6 的字幕数据一键导入到文字轨

### 任务 7：贴片/装饰元素 + 视觉特效

**任务描述**：实现贴片（表情/特效贴纸、边框装饰）和视觉特效（调色、粒子、镜头效果）。

**开发概设**：

#### 7a. 贴片/装饰

贴片作为 `timeline_item`（`item_type = 'sticker'`）放在贴片轨上。

- **表情贴纸**：漫画常用视觉符号（汗滴、怒筋、问号、爱心、星星眼、省略号）
  - 内置 20+ 静态贴纸（SVG/PNG）
  - 带简单动画（弹出、浮动、抖动）
  - 用户可导入自定义图片作为贴纸

- **特效贴纸**：火焰、闪电、冲击线、速度线、光效、花瓣飘落
  - 内置 10+ 动态特效（序列帧或参数化动画）
  - 可调参数：强度、方向、颜色

- **边框装饰**：
  - 漫画格边框叠加（黑色粗线框、圆角框、不规则手绘框）
  - 分屏模板（2 格、3 格、4 格布局）
  - 位置和大小可调

- FFmpeg 实现：所有贴片预渲染为带透明通道的 PNG 序列 → `overlay` filter 叠加

#### 7b. 视觉特效

- **调色/滤镜**：
  - 内置 10 个情绪预设：暖调、冷调、怀旧、黑白、高对比、低饱和、夜景、黄昏、梦幻、恐怖
  - FFmpeg 实现：`colorbalance`, `eq`, `hue` filter 组合

- **粒子特效**：
  - 6 种常用粒子：雪花、樱花、雨滴、尘埃、火星、光斑
  - 参数：密度、速度、方向、颜色
  - FFmpeg 实现：预渲染粒子序列（透明 PNG/WebM）→ `overlay` filter 循环叠加

- **镜头效果**：
  - 暗角（`vignette` filter）
  - 漏光/光晕（预渲染素材 overlay）
  - 色差（`rgbashift` filter）
  - 背景虚化（`boxblur` / `gblur` filter + mask）

- 特效优先级：调色 > 粒子 > 镜头效果。粒子和镜头效果为可选增强项。

**验收标准**：

### 任务 8：导出增强

**任务描述**：增强导出功能，支持多宽高比、平台预设、封面帧生成。

**开发概设**：
- **宽高比变换**：

  - 自定义：用户指定分辨率/码率/格式

- **封面帧**：
  - 从视频中选取任意帧作为封面
  - 自动推荐：选取画面信息量最大（色彩丰富度/清晰度评分最高）的帧
  - 封面导出为独立图片文件（JPG/PNG）
  - 可在封面上叠加标题文字（复用花字模板）

- **批量导出**：选择多集 → 一键按相同设置导出所有集

**验收标准**：

- [ ] 批量导出多集，进度逐集显示
- [ ] CLI 支持 `--ratio 9:16 --platform douyin` 参数
